## Project purpose

Design, develop, test, and document a knowledge-based application using logic-programming techniques. The application must represent knowledge using facts and rules and use logical inference to answer queries or solve problems within a selected domain.

## Required concepts

The brief names the following concepts:

1. Facts and predicates representing entities, properties, and relationships.
2. Rules deriving information from logical relationships and conditions.
3. Queries retrieving information or testing relationships.
4. Unification, term matching, and variable binding.
5. Backtracking and alternative solutions.
6. At least one meaningful recursive predicate where appropriate.
7. Lists and list-processing operations.
8. Arithmetic and comparison predicates where required.
9. Knowledge-based reasoning.
10. An appropriate input/output mechanism.
11. Tests for valid queries, invalid inputs, edge cases, and expected results.
12. Documentation explaining knowledge representation, rules, queries, and reasoning.

## Eight stages and deliverables

| Stage | Focus | Deliverable / evidence required by the brief |
|---|---|---|
| 1 | Problem identification and proposal | Problem statement, objectives, scope, required knowledge, intended users and outputs, and why logic programming is suitable. |
| 2 | Knowledge representation using facts | Prolog source containing facts and working retrieval queries. |
| 3 | Rules and logical inference | Facts, rules, demonstrated inference queries, and tests with different fact combinations. |
| 4 | Unification and backtracking | Working multi-solution queries and an explanation of variable binding and alternative search. |
| 5 | Recursion and lists | Meaningful recursive predicates and tested list-processing functionality. |
| 6 | Arithmetic and advanced rules | Arithmetic/comparisons, multiple-condition rules, and negation as failure or cut where appropriate, with tested queries and evaluation. |
| 7 | Integration and testing | Coherent application, organized source, user interaction, requirements testing, and correction of logical errors. |
| 8 | Final report and presentation | Complete Prolog source, report, presentation, demonstration of features, test results, limitations, improvements, and oral defense. |

## Ten expected submission deliverables

1. Project proposal and problem specification.
2. Knowledge-representation design.
3. Prolog facts and rules.
4. Queries demonstrating functionality.
5. Unification, backtracking, recursion, and list implementation where appropriate.
6. Completed application source code.
7. Test cases and results.
8. Technical documentation and user instructions.
9. Final project report.
10. Project demonstration and oral defense.

## Submission guidelines

- The project may be completed individually or in a group.
- Prolog must be the primary programming language.
- Facts and rules must be meaningful and relevant to the selected problem.
- Students must demonstrate working queries and explain their results.
- Source code must be clearly organized and appropriately commented.
- Major predicates must be tested with suitable examples.
- External sources and knowledge used must be acknowledged.
- A **Google Drive video link** explaining the project must be submitted.

The brief gives no prescribed presentation file type or report word count. This repository includes a Markdown report and a PowerPoint deck as feasible formats. No recording, upload, sharing-permission check, or final submission is claimed; see the submission checklist and video script.

## Current project interpretation and safety boundary

The proposed domain is an educational comparison of symptom terms against a limited, source-linked knowledge base for malaria, seasonal influenza, measles, and common cold. That scope remains proposed pending team/lecturer review. The application does not provide diagnoses, probabilities, treatment, urgency, emergency advice, or traffic-light recommendations. It does not claim to identify disease presence or absence.
